## 0.1.0 (2026-11-17)

First release.

### SDK core

- First release of the Python SDK, generated by sdkgen from the OVHcloud API's OAS3 specs.
- OAuth2 service accounts (client credentials), from `OVH_CLIENT_ID`, `OVH_CLIENT_SECRET` and
  `OVH_REGION`, or your own token source.
- One attribute per API section on the client, loaded on first use: `client.vrack`.
- Typed exceptions for each common status: `NotFoundError`, `ForbiddenError`... An error names
  the operation and, on a 401 or 403, the IAM actions it needs.
- Iterators over v2 lists paginated by cursor (`all_x`), and over v1 lists of IDs.
- `wait_ready`, `wait_task`, `wait_gone` and `wait` for asynchronous work.
- `read_only` and `allowed_operations` client options, checked before anything is sent.
- Retries, off by default, with the same limits as the Go SDK.
- v2 requests send `X-Schemas-Version`: the contract the SDK was generated from, whatever the
  account's own setting.
- `AsyncClient` for asyncio programs: the same arguments, sections and methods, with `await`.
  Iterators are async. The wait functions have `async_` forms.
- Request bodies never carry the fields the API sets (read-only). A body whose type has some
  takes `<Type>Writable`. `obj.writable()` turns what a GET returned into that form.
- A path without its API version (`/me`, or python-ovh's `/1.0/me`) is refused before it is
  sent, with a hint: `did you mean /v1/me?`. Before, the API answered a plain 404.
  `match_operation` reads `/1.0/` as `/v1/`, and tries `/v1` then `/v2` for a path with no
  version.
- A dict body given to a generated method is turned into its body model. snake_case names are
  sent by their API names. A dict that does not match raises `InvalidRequestError`. Its
  `NOT_GIVEN` values are left out, at any depth. The raw calls (`client.post`...) still send a
  dict as it is.
- A `datetime` with no time zone in a body is refused with `InvalidRequestError`, like in a
  query. Before, it was sent without an offset.
- Timeouts raise `RequestTimeoutError`, a `TransportError` that is also a `TimeoutError`.
- `ovhcloud.path(template, **params)` builds a path and escapes its values, like Go's
  `ovh.Path`.
- The raw calls (`request`, `get`, `post`, `put`, `patch`, `delete`) take an optional
  `result=` type, and return that type.
- `obj.to_dict()` and `obj.to_json()` on every model give the object as the API writes it:
  API names, only the fields that were set, no warnings. A field of the API named `to_dict`
  or `to_json` gets a trailing `_`.
- `ovhcloud.is_validated(obj)` is `False` for an object decoded without validation, because
  the response did not match its schema. Then a required field can be `None`.
- `repr()` and `print()` of a model show only the fields that were set, and the unknown ones.
  Before, they showed every field, with `None` for the unset ones.
- `Client` and `AsyncClient` take `retry_sleep=`, the function that waits between retry
  attempts. Tests pass one that does not sleep.
- Enum fields of request bodies (`<Type>Writable` and inline bodies) are typed `Enum | str`,
  so pyright accepts a string. A known value still becomes the enum member.
- `all_x` iterators of v1 lists document the list's arguments, and the IAM actions of the
  list call and the get call.
- Each section module and its `XxxApi` classes have an overview: the number of operations,
  the route prefixes, the list methods to start from, and the index file.
- A deprecated model field says `Deprecated` in its docstring, like in the Go SDK. Reading it
  does not warn.
- The wheel ships `AGENTS.md` and `llms.txt` next to `index/`, in the installed package
  (`ovhcloud/AGENTS.md`, `ovhcloud/llms.txt`). An agent with no network finds them there.
  The guide (`README.md`), `CHANGELOG.md` and `CONTRIBUTING.md` ship with them, so their
  links work.
  `help(ovhcloud)` names these files.
- The guide has new parts: coming from python-ovh, testing your code (mocked API, static
  token, no retry sleeps), and observability (httpx event hooks, OpenTelemetry, the query
  ID). `AGENTS.md` and `llms.txt` have the same points in short.
- The index README, the guide and `AGENTS.md` document the `iam` field of the index: collect
  it for the methods a program calls to know what to grant its service account.
